# Scientific scope and interpretation

The package implements a transparent MATLAB workflow for sensor or already-reconstructed source data. Its numerical core currently includes a dataset validator, time windows, geometry neighborhoods and adjacency, searchlight RDMs, a condition-aligned descriptive fixed-effects RDM mean, aligned model comparison, descriptive static GLM, time-matched lagged GLM, dynamic model comparison, batched static searchlight mapping, conditional label permutations, subject-level group sign-flip inference, and BH adjustment. Sensor/source file readers and plotting functions are present in the tree. **Presence of a function is not a claim that a particular instrument, format or publication analysis has been validated end to end.** The release test record should report exactly which MATLAB version, synthetic checks, public-example run and fresh-install path passed; until that record is complete, these are implementation statuses, not scientific performance claims.

`rsa_meeg.rdm.searchlight` returns condition-pair distances over centers and windows. Correlation or squared-Euclidean distances describe geometry. Crossnobis requires genuinely independent data folds for each condition and an explicitly suitable precision estimate; its numerical value and statistical interpretation depend on those choices. `rsa_meeg.rdm.average` gives each subject equal weight at each finite pair/center/window entry and records valid counts; it is not a random-effects population analysis, and multispatial-center averaging requires acknowledged registration. A searchlight location identifies where a chosen neighborhood is informative under the model and geometry, not the exact cortical origin of that information. Sensor mixing, inverse-solution leakage, feature count, noise covariance and overlapping neighborhoods can affect location and effect size.

`rsa_meeg.mapping.compare`, `glm`, `dynamic` and `dynamic_glm` report descriptive fits. `mapping.searchlight` batches RDM computation then static model comparison to reduce retained RDM memory; it does not change the scientific estimand. RDM entries share conditions and are dependent, so a standard correlation or regression p-value based on treating all pairs as independent is not warranted. Model labels and time alignment must be explicit; a model's predicted neural time equals model time plus lag in the dynamic interfaces. `dynamic_glm` fits a separate OLS at each matched time and lag; it does not infer an optimal lag. If model, ROI, window, radius or lag selection uses the same observations later tested, the reported inferential p-values do not account for that selection unless the full selection is nested inside resampling or assessed on independent data.

`rsa_meeg.inference.condition_permutation` tests fixed-effects condition-label exchangeability, keeping one label rearrangement coherent across the tested map; it does not generalize by itself to a population. `rsa_meeg.inference.group` uses independent subjects as units and a common whole-map sign flip per subject. Validity requires the relevant zero-null sign symmetry and a predeclared test family; cluster methods additionally require a defined adjacency and threshold. A significant cluster supports a family-level cluster statement, not significance at every included vertex/time sample or exact onset/localization. BH-adjusted p-values control an FDR target under their applicable dependence conditions and must not be described as FWER. Report the actual number of subjects, tests, permutations, correction family, tail and effect/uncertainty summaries.

This package does **not** perform M/EEG preprocessing, forward/inverse source reconstruction, biological model construction, independent precision estimation, searchlight hyperparameter selection, or automatic replication of historical papers. The 2014 tonotopy result and older simulation figures are prior work. A tiny public-sample excerpt may test file loading and computation paths, but it cannot establish sensitivity, calibrated false positives, source localization, superiority to univariate analysis, or superiority of source over sensor RSA. Those claims require preregistered or clearly scoped ground-truth simulations, matched comparisons and independent real-data validation. Existing source-space ssRSA and MEG/EEG RSA tools must be cited when discussing novelty: [Su et al. (2014)](https://doi.org/10.3389/fnins.2014.00368), [Nili et al. (2014)](https://doi.org/10.1371/journal.pcbi.1003553), [CoSMoMVPA](https://cosmomvpa.org/), and [MNE-RSA](https://mne.tools/mne-rsa/stable/index.html).
