# Migration and source provenance

This is a new `+rsa_meeg` MATLAB implementation with an explicit dataset, RDM, mapping and inference interface. It is **not** an in-place update of the historical `+rsa/+meg` package, and old calls or numerical outputs are not promised to match. The machine-readable [source locks](../provenance/source-lock.json) identify the historical commits and published 2014 archive; [migration.tsv](../provenance/migration.tsv) assigns every one of the 48 `.m` files in the 2018 integrated `+rsa/+meg` tree (39 main and 9 `+glm`) to a release status. The same table covers all 14 DNN `scripts/*.m` candidates, 5 tonotopy application files, 15 phonetic/GMM application entries (including one pinned non-default fix branch), and 61 first-party HTK/model-side entries. Third-party HTK dependencies are deliberately outside this mapping and are not bundled.

The table uses three statuses. `implemented_conceptual_partial` points to a real new component with related purpose; it does **not** assert the old input contract, algorithm, speed, result, or statistical interpretation was reproduced. `deferred` means the old capability has no supported counterpart here. `archive_excluded` means a study-specific or optional historical component is not part of the public runtime. Each row has the source file's SHA-256 and commit. The 2014 Software S1 ZIP has its own SHA-256 in `source-lock.json`; that frozen paper attachment is distinct from the official MATLAB repository's later `develop` commit.

For current analyses, construct `rsa_meeg.dataset` from observations × features × time with explicit condition labels, sample times and (for crossnobis) independent fold labels. Use one physical channel type per analysis: EEG, magnetometers and gradiometers have different units. `rsa_meeg.rdm.searchlight` replaces the *idea* of ROI, moving-window and sensor/source searchlight RDM calculations; `rsa_meeg.rdm.average` makes an equal-subject, NaN-aware descriptive fixed-effects mean only after conditions, windows and spatial centers are aligned. `rsa_meeg.geometry` defines neighborhoods or mesh/time adjacency. `rsa_meeg.mapping` compares explicit, aligned model RDMs, fits descriptive static or time-matched lagged GLM weights, and provides a batched static searchlight mapping path. `rsa_meeg.inference.condition_permutation` is conditional fixed-effects label permutation; `rsa_meeg.inference.group` performs subject-level sign-flip max-stat, cluster-mass or TFCE inference with its stated assumptions. Legacy `+glm` study scripts, implicit file ordering, old result caches, queue/email operations and optional dynamic time warping are not accepted by this interface. See [scientific scope](SCIENTIFIC_SCOPE.md) before interpreting results.

Historical attribution and rights are source-specific. The standalone RSA-MEG repository contains a BSD-style `Documentation/LICENCE.txt`; the later MATLAB RSA toolbox contains LGPL-v3 `Documentation/license.txt`, and third-party files can carry other terms. The DNN and phonetic application repositories have no repository-wide license grant that would justify calling all their code MIT. This package uses an independently written implementation informed by published concepts and audit, without wholesale copying of unlicensed application files. Consult the package `COPYING` and each source's notices before any redistribution of source from those older repositories. The provenance table records a research trail, not an assertion that the present package has imported those files.

Method priority is separate from code-release priority. [Su et al. (2014)](https://doi.org/10.3389/fnins.2014.00368) explicitly describe source-space spatiotemporal RSA, cite Su et al. (2012), and state that a MEG/EEG extension of the [Nili et al. (2014)](https://doi.org/10.1371/journal.pcbi.1003553) RSA toolbox was used. The official MATLAB repository retains a `meg-pre-alpha` tag pointing to a commit dated 2015. The current package therefore makes no claim to be the first MEG/EEG RSA or ssRSA method, nor the first public MEG extension. Source commits prove lineage and availability of code snapshots, not scientific validation or authorship of every algorithm.

Historical commit/tag dates alone do not establish the first date a repository became public. The currently accessible source snapshots and the 2014 paper describe different kinds of evidence.
